# Проверка пилота 0.2

Автоматические проверки и сборка не заменяют испытание реального будильника.
Перед ежедневным использованием требуется отдельный прогон на телефонах.

## На устройстве

1. Выдать системные разрешения по одному. Отказ должен оставлять понятное
   сообщение и не создавать ложное впечатление активного будильника.
2. Поставить тестовый звонок, заблокировать экран и дождаться звука.
3. Повторить без сети, с закрытым приложением и в режиме энергосбережения.
4. Использовать все переносы; перезапустить приложение между переносами.
   Счётчик не должен обнуляться. Задание должно оставаться доступным.
5. Открыть задание: Android продолжает звонить до верного решения.
6. Проверить аварийный выход, а также обычную системную остановку на iOS.
7. Перезагрузить Android до времени будильника, в том числе не разблокируя
   телефон после запуска. Проверить восстановление расписания.
8. Проверить одноразовый будильник, будни/выходные, несколько будильников,
   смену часового пояса и переходы летнего/зимнего времени.
9. Проверить звук с Bluetooth-наушниками и во время другого аудио.
10. Проверить большие шрифты, экранную клавиатуру, TalkBack/VoiceOver и
    горизонтальную ориентацию; задания не должны блокировать аварийный выход.

## Честные ограничения

- Нет проверки фактического пробуждения или длительности сна.
- Обход задания через системную остановку iOS допустим архитектурой AlarmKit.
- Режим принудительной остановки Android снимает гарантии доставки.
- Web не является будильником.
- Доставка события в Flutter сама по себе не доказывает воспроизведение звука.

## Подтверждённые результаты

- Flutter 3.47.7, Dart 3.13.5: `flutter analyze` без замечаний.
- 56 Flutter/Dart-тестов: модель и задания, сохранение состояния, ошибки
  хранилища, пересекающиеся срабатывания, диалог аварийного выхода;
  проверочный звонок, отмена только пробного события, восстановление после
  сбоя между нативным планированием и записью Flutter, ручное подтверждение
  результата, миграция данных 0.1 и узкие экраны с крупным шрифтом.
- 15 Android JUnit-тестов: расписание, лимит переносов, проверка конфигурации
  и аварийное отключение при ошибках хранилища; допустимая задержка теста
  и защита обычных будильников от отмены через проверочный API.
- Оптимизированный APK для Android arm64 собран в release-режиме.
  Используется отладочный ключ, для публикации в магазине он не подходит.
- iOS Simulator: Swift-мост AlarmKit успешно скомпилирован в macOS CI
  (`flutter build ios --simulator --debug --no-codesign`).
- Реальные Flutter-виджеты отрисованы для снимков главного экрана,
  каталога заданий, задания на счёт, настройки проверки телефона,
  ожидания звонка, ручного подтверждения и экрана подъёма с бюджетом переносов.
  Снимки используют подставной нативный шлюз и не доказывают доставку звука.

CI отдельно собирает web, Android APK и iOS Simulator. Актуальные результаты
доступны во вкладке Actions приватного репозитория. Испытания на физических
Android/iPhone пока не выполнены.

Короткий сценарий и незаполненный журнал проверки на устройстве: [PILOT.md](PILOT.md).
