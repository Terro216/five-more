# Выпуск Android через GitHub

Репозиторий остаётся приватным. Канал обновлений — GitHub Releases;
Obtainium получает APK оттуда. iOS и магазины требуют отдельной настройки.

## Следующий выпуск

1. Увеличь обе части `version` в `pubspec.yaml`, например `0.5.2+7`.
   Номер `+7` — Android versionCode: он должен строго возрастать.
2. Добавь `docs/releases/v0.5.2.md` с изменениями и границами проверки на телефоне.
3. Закоммить изменения и отправь `main` в GitHub. Проверь обычный CI.
4. Из чистой локальной `main`, совпадающей с `origin/main`, выполни:

   ```sh
   bash scripts/publish_android.sh
   ```

Скрипт проверит версию, историю тегов и заметки, создаст тег `v0.5.2` и отправит
его. Workflow **Publish Android release** проверит принадлежность тега `main`,
выполнит форматирование, анализ, Flutter-тесты, сборку APK и Kotlin-тесты.
SDK закреплён в `.flutter-version` и `.flutter-revision`; lockfile обязателен.

Перед публикацией проверяются package ID, версия, versionCode, сертификат,
отсутствие debug-флага и сетевого разрешения, наличие ARM/ARM64/x86-64.
Workflow загрузит файлы в черновик Release, скачает их обратно и сравнит байты
и SHA-256. Только после успешной проверки выпуск станет доступен Obtainium.
Полномочие `contents: write` есть только у задания публикации.

Файлы выпуска:

- `five-more-X.Y.Z-universal.apk` — один APK для установки и обновлений;
- `five-more-X.Y.Z-sha256.txt` — контрольная сумма APK;
- `five-more-X.Y.Z-build-info.json` — исходный commit, версия, SDK и сертификат.

GitHub-флаг prerelease выключен, чтобы обновления находились стандартной
настройкой Obtainium. Это выбор канала распространения: приложение по-прежнему
пилот, а результат звонка подтверждает пользователь на реальном устройстве.

## Постоянная подпись

Сертификат зафиксирован в `.android-signing-certificate.sha256`:

```text
f952b5d8a0a122d6e2711e4010a9b278dafd51b296bce73145ef7135ebbe8089
```

Это прежний сертификат Android Debug из пилота 0.5, сохранённый намеренно для
совместимости обновлений. Срок действия — до октября 2056 года. Приватный ключ
перенесён в отдельный контейнер с новым случайным паролем; сам сертификат
не меняется. Это постоянный ключ данного частного канала, не магазинная подпись.
Заменять его новым случайным ключом при переносе сборки нельзя.

GitHub Actions secrets:

| Имя | Назначение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | Закодированный контейнер с приватным ключом |
| `ANDROID_KEYSTORE_PASSWORD` | Пароль контейнера |
| `ANDROID_KEY_ALIAS` | Имя ключа |
| `ANDROID_KEY_PASSWORD` | Пароль ключа |

Workflow извлекает ключ только в `$RUNNER_TEMP` после Flutter-проверок и удаляет
его в завершающем шаге, включая случай ошибки. В артефактах находятся только
APK и открытые метаданные. Без ключа обычная release-сборка завершается ошибкой.

Для локальной подписанной сборки передай `ANDROID_KEYSTORE_PATH`,
`ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
Для одноразовой сборки разработчика можно явно задать
`FIVE_MORE_ALLOW_DEBUG_SIGNING=true`; такие APK нельзя распространять как обновления.
Обычный CI использует именно этот отдельный путь и не получает секретов подписи.

## Ошибка сборки и откат

Если workflow упал до публикации, предыдущий Release остаётся доступен.
Исправь причину и повтори workflow для того же тега; незавершённый черновик
можно дозаполнить автоматически. Если менялись исходники, нужен новый номер
версии и новый тег. Опубликованный Release workflow не перезаписывает.

Для отката приложения перенеси нужные исправления в новую версию с большим
versionCode. Android обычно запрещает downgrade; удаление приложения ради
отката стирает данные. Не перемещай старые теги и не заменяй APK готового выпуска.

Физические проверки ведутся отдельно по [PILOT.md](PILOT.md). CI не подтверждает
услышанный звонок, сохранность состояния после настоящего обновления на телефоне
или установку в конкретной версии Obtainium.
